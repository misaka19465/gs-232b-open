# ESP-IDF ADC 采样适配

入口为 [`esp_adc.h`](../include/gs232b/esp_adc.h)，实现为 [`esp_adc.c`](../src/platform/esp_adc.c)，已加入 ESP32-C3 固件组件和 `esp_adc` 依赖。适配器提供采集入口与 `gs232b_sampler_t` 缓存端口；应用组合层负责 5ms 采集任务和启动顺序；`app_main` 已启动统一控制任务。

| 项目 | 配置 |
| --- | --- |
| 方位 AZ | GPIO1 / `ADC_UNIT_1` / `ADC_CHANNEL_1` |
| 仰角 EL | GPIO0 / `ADC_UNIT_1` / `ADC_CHANNEL_0` |
| ADC 位宽 | `ADC_BITWIDTH_12`，原始码 0..4095 |
| 衰减 | `ADC_ATTEN_DB_12`，C3 最高档，有效量程上限约 2.5V，覆盖分压后约 1.753V 满量程 |
| 芯片校准 | 每轴持有一个 `adc_cali_create_scheme_curve_fitting` 句柄，配置与采样通道、衰减和位宽一致，驱动验证出厂 eFuse 数据 |
| 电压 | `adc_cali_raw_to_voltage` 的毫伏结果乘 1000，得到 ADC 引脚微伏；保留原始计数用于诊断 |

不使用默认 Vref、`raw / 4095 × 3.3V` 或固定满量程反推 ADC 电压。板上分压和两轴角度换算由反馈/运动核心处理，适配器不重复放大到控制箱端电压。

## 生命周期与投递

1. 在输出初始化并确认全停后，以清零的 `gs232b_esp_adc_t` 调用 `gs232b_esp_adc_open`。只有 ADC、两轴配置、校准和单槽队列全部建立成功才打开；尚未采集时读端口返回 `GS232B_ERROR_NOT_READY`。
2. 将 `gs232b_esp_adc_sampler(&adc)` 交给运动核心。在单独的采集任务中周期调用 `gs232b_esp_adc_capture(&adc)`，建议每 5ms 一轮、每轴 200 samples/s；该函数不创建任务。当前工程 FreeRTOS tick 为 10ms，不能使用 `vTaskDelay(pdMS_TO_TICKS(5))` 实现该周期。接入时可由 5ms `esp_timer` 通知采集任务，任务合并通知后只采一轮，避免补采过去时刻；定时器/ISR 回调不做 ADC 转换。
3. `capture` 在采集任务内顺序执行两次同步 oneshot 读取和校准，分别在原始读取返回时盖单调微秒时间戳。每轴通过 `xQueueOverwrite` 零等待覆盖长度为 1 的最新样本队列；慢消费者不阻塞生产者，也不积压历史样本。两轴独立投递，不承诺同时采集。
4. `sampler.read` 只执行 `xQueuePeek(..., 0)` 和时间检查，不访问 ADC、不校准、不等待生产者、不消费或刷新样本时间。重复读取返回同一采样，运动核心按采样时间去重。新样本覆盖旧值；样本失效后必须有下一次成功采集才可恢复。
5. 停止采集调度并确保所有读者退出后调用 `gs232b_esp_adc_close`。关闭立即使端口未就绪；释放失败可重试，重复关闭安全。重开不会保留上一次采样。

`open/close` 必须与所有读写串行；运行期间只允许一个采集所有者，可并发读取。实例和队列不可由外部直接访问或复制。oneshot 的同步等待只出现在采集任务内，不能放进运动循环。生产者停顿时，缓存仍在 100ms 新鲜度预算内可读；超过预算后读端口报告未就绪。

## 失败与就绪状态

| 情况 | 行为 |
| --- | --- |
| eFuse 校准不支持、校准句柄创建失败 | `open` 返回 `NOT_READY`，清理已取得资源；所有轴保持未就绪 |
| ADC 初始化/配置、队列分配失败 | 返回对应资源、占用或 I/O 错误；不开放部分初始化的实例 |
| oneshot 超时/失败，校准转换失败 | `capture` 返回 `NOT_READY`，以无效样本覆盖失败轴的旧值；继续采集另一轴 |
| 原始码不在 0..4095，校准电压负值或超过 2500mV，获取时间为负 | 同上，绝不截断、溢出或伪造有效电压 |
| 无样本、无效样本、未来样本或年龄超过 100ms | `sampler.read` 返回 `NOT_READY`，整个输出样本清零 |
| 校准电压超过板上反馈满量程，但仍在 ADC 有效范围内 | 保留校准电压交给核心；核心报告 `HARDWARE_FAULT`，避免把真实过压降为正常角度 |

两轴最新队列不保存历史错误：后续成功采样会恢复对应轴的读数。已被运动核心识别的采样故障会清除滤波窗口、撤销双轴动作并锁定故障；后续有效采样不会自动解除故障或恢复旧运动，仍需显式清除。

## 验证

运行 `python3 scripts/test.py` 构建 `esp32-c3-wroom-02u-n4` 并执行原生测试。两个新增目标直接编译实际平台适配器，只有这些目标可见 `tests/fakes/esp_idf` 中的 IDF API 替身：

| 目标 | 覆盖 |
| --- | --- |
| `esp_adc_tests` | 通道、位宽、衰减和逐轴校准配置；驱动校准结果及毫伏→微伏；真实获取时间与缓存过期；零等待单槽覆盖；读取与生产者并发时样本完整；每轴采样/校准失败和不合理数值失效；初始化失败释放、关闭失败重试、重开无旧值 |
| `esp_adc_motion_tests` | 实际 ADC 适配器→sampler→反馈→运动→输出管理器；缺出厂校准拒绝运动，采集/校准失败及陈旧反馈触发双轴全停，过量程传播硬件故障，恢复读数后仍需清故障且不自动恢复旧动作 |

原生替身验证 API 调用和软件传播，C3 编译验证实际 IDF 6.1 API 兼容性。实际输入电压、eFuse 数据、采样噪声与 5ms 调度仍需板上实测。
