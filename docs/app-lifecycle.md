# 组合入口与任务边界

组合根为 [`app_main.c`](../src/app_main.c)，平台无关编排见 [`app.c`](../src/app/app.c)。`app_main` 先同步完成安全输出和复位请求，再把唯一串行所有权转交 `gs_control`。该任务持有输出管理器、复位协调器、运动核心、dispatcher 和网络服务；SDK 事件/RMT/采样定时回调只复制固定值或投递通知，不调用 dispatcher、运动或 NVS。

启动顺序固定为：

1. 打开共享 SPI/LEDC，输出管理器立即提交 `0x00` 和 PWM=0。
2. 发起 W5500 复位，控制任务按提交完成时间等待复位低脉宽及释放后的恢复窗口；等待期间不初始化网络、ADC 或协议会话。
3. 复位就绪后由 `gs_store` 打开 NVS 并预读全部分域双槽；启动 ADC 采集任务并加载两轴零点。缺记录独立保留 `zero_error`，不等待反馈就绪。
4. 初始化运动核心和 dispatcher，连接完整会话键的 UART/WS 路由，恢复显示、管理认证和网络域，绑定网络/AP 请求邮箱。
5. 打开 UART，完成 15 秒内的波特率匹配/回退并 attach，一次排队 `Connect OK`。匹配阶段每 RTOS tick 轮询，其他运动入口尚未开放。
6. 独立尝试 Ethernet、统一 STA/AP、HTTPD；Ethernet 接管已完成的复位，不再重复首次脉冲。任何接口失败都不会跳过 UART 或其他接口。随后持续执行 UART service → 网络事件/WS service → dispatcher tick → UART service。

| 任务/通知 | 周期、优先级、栈预算 | 所有权与有界队列 |
| --- | --- | --- |
| `gs_control` | 运行阶段 20ms 绝对周期，优先级 10，10240B | 唯一核心所有者；延迟后不补跑历史 tick；请求正文池 2KiB，控制描述符/序列双缓冲沿用核心上限。 |
| `gs_adc` | 5ms timer 通知，优先级 9，3072B | timer 仅发通知，任务合并通知后采一轮；每轴一个覆盖邮箱，100ms 新鲜度门禁。 |
| `gs_uart_rx` | 驱动事件，优先级 8，3072B | 32KiB RX ring、32 个事件、8×256B 带会话/epoch 数据包；TX FIFO 4KiB，控制端零等待。 |
| `gs_eth` / `gs_sta` | 工作请求，优先级 3，各 4096B | 各一槽请求/结果、一槽带序号屏障确认；各 16 个 SDK 事件，每轮最多消费 4 个；溢出撤销地址及旧会话。 |
| HTTPD | 优先级 3，SDK 栈预算 | 最多 4 个 WS；每连接 16KiB 有界 RX、4KiB TX；任务负责网络读写，控制端每轮最多 feed 256B。 |
| `gs_store` | 存储请求，优先级 2，4096B | 一槽按值请求/完成队列；启动预读双槽，运行读 RAM，只有此任务访问 NVS handle。 |

Flash 保存/擦除只有在输出已知全停、无手动/定位意图、无待换向且没有运行序列时才入队；其他状态直接返回 BUSY。串行控制所有者此时等待存储任务实际完成，期间不接纳新动作，保留“成功即已落盘”的同步契约。SPI/PWM 输出和正在运动的控制周期中不执行 Flash。写入失败不更新 RAM，不重复自动写入；不设置会误报取消的提交超时。NVS 初始化失败保留 `store_error`，读端降级为无记录，运动门禁关闭，UART 查询与网络恢复仍可用，写入返回原存储错误。损坏的显示或管理认证记录拒绝 dispatcher 启动，不静默覆盖已有数据。

[`board_config.c`](../src/app/board_config.c) 保持 `parameters_verified=false`；换向 250ms、容差、超时和四档 PWM 都是开发参数。完成控制箱实测并更新固件参数后才可打开门禁。`!MOTION STATUS` 同时暴露 `parameters_verified`、每轴 `motion_ready`、零点/反馈/位置有效性；缺零点或未实测显示 DISABLED，缺反馈显示无效位置及 NOT_READY，均拒绝手动和定位。未实测时仍可查询有效位置及使用 O/O2 保存零点。

输出初始化、复位提交或控制任务创建失败时停留 FAILED，不自动重试未知输出。ADC/采集任务失败时保持反馈无效；网络/HTTPD 失败独立保留错误，既有 UART 不受影响。网络重建期间先发布不可用接口并撤销旧完整会话，再接纳新输入；扫描使用 STA 工作任务并轮询结果，不停止现有接口，也不阻塞运动。配置请求和 AP start/stop 回调只覆盖各自的一槽完整值邮箱，忙时留存最新请求。

主机验收见 `app_startup_tests`、`esp_store_worker_tests` 和网络生命周期测试；`scripts/test.py` 检查默认 ELF 的组合根、全部真实外设路径以及四个额外 API 链接环境。SDK 仅启用产品已支持的开放网络/WPA2-Personal，不带 WPA3/OWE/企业认证，保持现有 1MiB 应用分区及所有持久化格式。仍需实板验证电气时序、真实捕获、堆/栈余量与机械参数；软件验收不代表这些测量已完成。
