# 所有权、停止优先与旧命令失效

接口见 [`command_control.h`](../include/gs232b/command_control.h)。控制核心已加入 ESP-IDF 组件和原生测试，无动态内存、RTOS 或传输依赖；通过同步执行端口接入运动和交互状态。M/W 增量上传、完整参数验证、双缓冲序列数据及定时状态机由核心持有。`app_main` 仍为构建基线，真实 UART/WebSocket、完整命令执行及响应编码须接入该边界后才能用于硬件控制。测试执行端直接驱动现有运动核心、输出管理器和序列计时；校准交互仍为测试替身。

## 所有权与权限

所有权包含完整的 `session_id + generation`，AZ/EL 共用一个控制者。普通请求在完整行通过语法和执行端验证后接纳，执行时再次验证活动会话、epoch、权限和动作前置条件。自动取权发生在执行第一条合法写控制请求时；查询和不合法的写请求不占用控制权。执行失败且没有接纳任何动作时撤销新取得的所有权。

| 输入 | 行为 |
| --- | --- |
| `C/B/C2/N/H/H2/H3`、扩展只读状态 | 所有活动会话均可查询；不取得或续占控制权。 |
| 运动、速度、序列、校准、显示设置 | 无控制者时自动申请；已有他人控制时拒绝。SoftAP 管理会话禁止取权及动作写入。 |
| `!OWNER GET` / `gs232b_control_snapshot` | 获取完整控制者键、传输类型、运动/序列/交互占用原因、epoch、队列及空闲计时状态。 |
| `!OWNER TAKE` / `gs232b_control_take` | 空闲且输出已知全停时申请；不抢占其他控制者。当前控制者重复申请可刷新空闲起点。 |
| `!OWNER RELEASE` / `gs232b_control_release` | 仅控制者可释放，要求已知全停、无待运行序列和交互；活动中返回 `BUSY`，可用 `S` 全停并撤权。 |
| `A/E/S` / `gs232b_control_request_stop` | 任何活动会话均可请求，包括普通请求队列已满时；不会自动成为控制者。 |

空闲释放采用单调时钟：无动作意图（包括换向等待）、输出已知全停、无待运行序列和交互时开始计时，达到 2 秒自动撤权。等待 `T`、运行序列的 999 秒间隔、校准交互及活动运动均保持控制权。只有成功的写请求或显式 `TAKE` 刷新空闲起点；半行、无效输入、普通查询和旁路查询不刷新。有效 M/W 输入预约期间暂停空闲撤权，释放预约后按原空闲起点继续判断，避免合法低速上传被中途作废。

`N` 和空行对交互会话可能是取消输入；入口和执行时均按来源会话与当时交互状态分类，不能让排队时的只读权限取消别人的交互。执行端仍须隔离交互输入，并对校准和显示设置执行各自前置条件。此核心不实现网络/持久化管理命令；未知扩展默认拒绝，不把未知命令视为只读。

## 有界调度与停止

每会话最多 8 条普通请求，总共最多 7 个活动会话、56 条请求。普通请求正文复制到调用方提供的固定字节池（至少 2KiB）；M/W 仅保存数字描述符，不占正文池。请求数或字节池任一耗尽时拒绝整条新请求，保留已接纳内容。每个活动会话独占至少 2KiB 行工作区，关闭后可复用；M/W 不保存整行。GS 的总字节上限仍为 CR 前 16384 字节，扩展上限为 2048 字节，均包含空格。会话和资源总预算由实际传输适配器进一步限制。

每次 `feed` 最多接纳 256 字节。`tick` 先处理独立停止槽，再推进运动/序列安全检查及半行超时，最多执行一条普通请求，然后检查空闲释放；查询洪泛不会让普通请求处理无限占用运动调度。适配器应在每个小块之间让出调度，并保持周期调用 `tick`。

## M/W 增量上传与提交

[`position_parser.h`](../include/gs232b/position_parser.h) 逐字节解析三位数字和空格，不保留原始长行；[`sequence_store.h`](../include/gs232b/sequence_store.h) 持有两份各 3800 个 `uint16_t` 的角度数组，active/staging 合计 15200 字节。M 长格式支持 2～3800 点，W 支持 2～1900 对；间隔须为 001～999。首参数与命令紧邻，字段间接受多个 ASCII 空格，首尾空格不改变命令含义。

第一个非空格字节 M/W 请求唯一输入预约。已有控制者时只有该控制者可预约；无控制者时先到的合法来源可预约。预约不是控制权，不设置目标或提交输出；其他会话仍可查询或请求 A/E/S，写操作及取权返回 `BUSY`。即使相同会话也不能用第二条 M/W 覆盖未执行的 staging。完整行进入队列后继续持有预约，直到该请求执行、拒绝或失效；因此在同一接收块中拼接多条上传也不能覆盖前一条参数。

CR 到达前只更新 staging，旧 active、已接纳目标和序列计时继续有效。CR 时校验语法、点数、W 配对、间隔、全部角度、轴能力、反馈/零点、软件限位和交互状态，再进入普通队列。实际执行前重新校验会话、epoch、权限、坐标和状态；任何校验失败都不交换缓冲、不取消旧计时或替换目标。

执行端先按 `position_plan` 接纳首点；成功后核心在同一串行边界将 staging 方位编译为机械整数度并交换 active/staging，控制核心的序列状态变为等待 T。P36 首点参考执行瞬间的当前位置，后续点参考前一点选出的机械角；软件限位排除最近解时继续检查另一个等价解。有效数据 `control.sequence.active` 已是机械角，W 按 AZ/EL 交错，不得再次按显示坐标解释；指针只保留到下一次成功替换或清除。单点 M/W 清旧序列；M 替换 W 序列时通过计划先停旧序列留下的仰角，独立的仰角手动动作继续。

`EMPTY / LOADED_WAIT_T / RUNNING / COMPLETED`、T、N 序号及绝对截止时间由核心统一维护，执行端不再提供序列状态。定时行为、替换/清除矩阵及超期边界见[定时序列状态机](timed-sequence.md)。序列完成后的空闲/显式释放保留末点序号和 active 数据。

语法错误、超限及非法字节立即释放输入预约并丢弃至 CR，在 CR 只报告一次错误。最后字节后连续 2 秒无新字节则立即报告一次超时、释放预约，旧 active 不变，迟到后缀仍丢弃到 CR。总发送时间不设 2 秒上限。正常 CR 校验失败、队列满、执行前拒绝或非控制者断开也释放预约；A/E/S、epoch 变更和故障同时作废预约、旧队列及半行。裸 M/W 属于协议特例：先通过权限检查，执行时清序列并全停，然后返回错误。

| 停止 | 同步执行的行为 |
| --- | --- |
| `S` | 清序列、交互和暂存任务，撤销两轴方向/目标/换向动作，提交全停，撤销所有权。 |
| `A` / `E` | 清序列、交互和暂存任务，立即停止对应轴；另一轴已接纳的单点或手动动作继续，保留所有权。 |
| 同周期 `A` + `E` | 停两轴但保留所有权；只有包含 `S` 才按全停撤权语义处理。 |
| 控制者关闭 | 在关闭 API 返回前全停、清任务并撤权；其他会话关闭不打断控制者。已接纳的旁路停止不会因来源关闭而撤回。 |

停止只识别由 CR 结束的完整独立命令行。序列参数或扩展负载中的 `S`、损坏行中的 `S`、没有 CR 的单字节 `S` 均不会触发停止。等待丢弃的半行必须先遇到其 CR，不能在该半行中嵌入停止；其他活动会话仍可提交独立停止。

停止槽用轴掩码合并，不占普通请求描述符或字节池。另有固定的每会话/每种停止应答计数；完成回调按来源和种类批量报告应答数，不需为每个停止分配正文。回调必须有界，不能为批量应答阻塞运动循环；实际 TX 池耗尽时由适配器处理慢客户端。停止输出失败仍清旧输入和所有权，并保留执行端的未知输出/故障状态，不假定物理已停。

## epoch 与会话生命周期

全停、单轴停止、控制者关闭、显式/空闲释放及首次运动故障均推进 epoch，并清普通请求队列。新的控制者必须经过撤权边界，因此跨控制者的旧命令不能被重新盖章使用。`A/E` 也作废旧输入，以防其前面排队的 `R/U/T` 在停止之后重启所选轴。

活动半行由 `gs232b_line_parser_invalidate` 静默作废，持续丢弃到下一 CR；不会简单清空后将剩余字节当作新命令。每条半行保存首字节上下文，补齐 CR 时不能用最新 epoch 覆盖它。

传输接入顺序：

1. `session_open` 返回由核心分配的完整会话键；关闭必须携带相同键。
2. 在字节进入任何上游 RX 队列前调用 `capture`，为每段输入保存会话键和 epoch。
3. 按至多 256 字节的小块调用 `feed`，始终携带原接纳上下文。旧 epoch 的块被消费并丢弃，跨块残行继续丢弃到 CR；旧 generation 的块完全不接纳。
4. 周期调用 `tick`；传输失联、读写故障或接口失效调用 `session_close`。不要用 UART 无法观测的握手信号虚构断线。

相同槽位复用时 generation 单调增加，旧键不能输入、取权、释放、停止或关闭新会话。计数器到达 `UINT64_MAX` 时不回绕：该会话槽位不再复用；epoch 无法推进时全停并永久拒绝新动作和取权，仍接受查询和停止。重启整个控制实例必须同时废弃全部外部会话、缓存和旧上下文。

## 执行端接入契约

所有 API、执行端和实际运动控制共用一个串行任务或外部锁。`validate` 只校验；`execute` 仅执行已获准的普通完整行；`cancel` 清所有交互/暂存任务但不提交方向，序列由核心清除；`stop(mask)` 撤销所选轴的动作并提交停止，保留另一轴已接纳的动作；`snapshot` 返回真实轴、交互及故障状态。故障由执行端锁定并全停，控制核心观察新故障后清旧任务、撤权，不重复重试失败输出；无法读取执行端状态时请求全停并撤权。运动故障不强行覆盖成功的查询响应；C/B 等查询仍由执行端判断所需反馈是否可用。

`position_context` 必须复制当前显示配置和两轴真实快照，包含启用能力、零点、反馈和实际软件限位；不能产生动作。M/W 的请求 `position` 是数字参数，`line` 为空，`validate` 不得再按字符串解析；只有 `execute` 收到完整验证生成的 `position_plan`。执行端必须先排除其余运行前置条件再改变动作，普通拒绝不得改变旧目标；输出失败按运动故障全停，不能继续旧任务。首点接纳后由核心原子提交存储并取消旧计时，后续点经 `sequence_target` 同步接纳机械角计划。`fault` 回调可接入 `gs232b_motion_abort`，锁定首次诊断、清两轴动作并尝试一次全停。裸 M/W 和 T 由核心处理，不调用 `execute`。

P36/P45/Z 的实际变更由核心依据轴活动、输出已知全停、序列计时及交互状态校验；执行端成功应用并持久化后，核心清除已加载或已结束的序列。普通失败保留旧序列，重复模式及 P45 下的 Z 保留序列。执行端的 `validate` 仍需校验自身配置前置条件。

`complete` 只通知来源会话，GS 错误仍使用现有响应编码器，不向普通 GS 流加入 `BUSY` 等扩展文字。`OWNER GET/TAKE/RELEASE` 的结果由该回调结合只读控制快照编码。回调中可以读取快照，不能重入修改 API；行视图仅在回调期间有效。执行端不能绕开该入口直接消费命令或保留未经 epoch 校验的动作队列。

M/W 完成通知只带命令类型、点数、格式和间隔元数据，`angles=NULL`；因为提交后的 staging 已转换为机械角，不能继续把原参数视图当成协议角度。`gs232b_control_snapshot` 另外返回 `sequence` 值快照、预约来源和是否已排队；N 使用其中的 `current_point / point_count` 经现有响应编码器输出。独立使用行解析器时必须提供 `gs232b_line_upload_t`：begin 只预约，abort 释放错误/超时半行；成功 CR 后接收方负责保留或释放该工作区。
