# GS-232B 多接口控制与硬件适配设计

## 1. 范围与设计决策

本项目保留 GS-232B 的控制、查询、显示模式、多点定时跟踪及交互校准语义，将控制入口改为 CH340K 转接的 UART1、W5500 以太网 WebSocket、Wi-Fi WebSocket。原生 USB 只承担调试日志和 USB Serial/JTAG；UART0 不作为控制或日志接口。

三个入口可以同时连接和查询，转台运动由一个控制会话独占。串口和两个网络接口共用一个协议内核、一个运动状态机及一套硬件驱动；响应按原请求会话返回，不广播 GS-232B 响应。所有会话都可以请求停止。

以太网默认 DHCP，提供固定 IPv4 配置；Wi-Fi 提供 UART1 配置凭据及 SoftAP 配网。**设备没有用户可操作的按钮，BOOT/RST 对用户不可达**：首次未配网时自动开 SoftAP，之后由 UART1 或可达的管理连接触发，不设计任何按键配网或按键恢复流程。配置使用独立前缀扩展命令，避免侵入官方命令命名空间。本次只规定设备端接口及其行为，不制作配网页面或任何上位机。

## 2. 硬件路径与固件约束

### 2.1 MCU、UART 和 USB 分工

U3 是 ESP32-C3-WROOM-02U-N4，3.3V 供电，4MB Flash。下表同时列出模组符号脚号及 GPIO，避免把脚号当 GPIO。

| 用途 | U3 脚号 / GPIO | 板上连接 | 设计约束 |
| --- | --- | --- | --- |
| UART1 TX | 5 / GPIO6 | `TXD_UART1` → R5 220Ω → U4 CH340K RXD（9） | 固件明确选择 UART1 并映射引脚。 |
| UART1 RX | 6 / GPIO7 | `RXD_UART1` ← U4 TXD（8） | U4 VCC（7）、V3（10）接 3.3V；这里是 3.3V 逻辑，不是 RS-232 电平。 |
| USB 调试 D− / D+ | 13、14 / GPIO18、19 | 分别经 R3、R2 22Ω 及 D1 USBLC6-2SC6 到 USB1 | 使用原生 USB Serial/JTAG；只发调试信息，不接 GS 命令解析器。 |
| USB 控制串口 | 通过 U4 到 GPIO6、7 | USB2 → D2 USBLC6-2SC6 → U4 UD−/UD+ | 主机使用 CH340 虚拟 COM；USB2 是正式控制入口。 |
| SPEED PWM | 11 / GPIO20 | 符号名 RXD，网络为 `SPEED_PWM` | 交给 LEDC，不初始化 UART0 RX。 |
| 未使用 | 12 / GPIO21 | `TXD_UART0` 无外接负载 | 不初始化 UART0 控制/日志；禁止默认 console 配置误占 UART0。 |
| BOOT / RESET | 8 / GPIO9；2 / EN | 启动配置与复位网络 | 用户不可操作，不作为配网、恢复或日常操作入口。 |

CH340K 的 CTS#、RTS#、DTR# 都是悬空未连接。必须关闭硬件流控；不能声称完整复制官方 CTS，也不能用 DTR/RTS 判断串口打开或掉线。UART1 不是此板的 ROM UART 下载口。应用、bootloader 的日志路由及 ROM 可能产生的 UART0 启动行为要分别核对；不为满足“UART0 不使用”而直接烧写不可逆 eFuse。本次不改变下载、JTAG 或调试配置文件。

### 2.2 各外部接口的实际接线

本板控制的是旋转器**控制箱的外部控制接口**，不是电机、电机绕组或市电；方向输出是模拟“按键接地”。板内没有光耦或隔离 ADC，所有信号共地。

| 功能 | H1（2×5） | PS1（6 针加屏蔽脚） | U2（DIN-804） |
| --- | --- | --- | --- |
| 仰角上 / 下 | 1 / 3 | 无 | 3 / 5 |
| 方位 CW / CCW | 2 / 4 | 1 / 2 | 2 / 4 |
| SPEED 输出 | 5、6 是同一个网络 | 3 | 无 |
| 方位反馈 | 8 | 4 | 6 |
| 仰角反馈 | 7 | 无 | 1 |
| 信号地 | 9、10 | 5 | 8 |
| 其他 | — | 6 未接；7、8、9 接地（壳脚） | 7 未接；9、10 接地（壳脚） |

H1 的两个 SPEED 脚相连，不是两个独立调速通道；板上也只有一个 PWM 和一个有效调速输出。U2 不带 SPEED，因此不能从该接口承诺仰角调速。PS1 与 U2 的方位控制及反馈网络直接并联；不能同时接两台方位控制箱，尤其不能让两个模拟反馈输出互相驱动。H1 是同组网络的引出，也不是隔离后的第三套接口。

方向脚通过与公共地短接来控制转动，速度输入为模拟电压。两路角度反馈统一以外部 4.5V 为满量程，零点偏置分别保存。

### 2.3 四路方向：74HC595 → AO3400A → 对地拉低

U5 `74HC595D,118` 由 3.3V 供电，方向输出顺序如下。位名 Q0/Q1 与器件位号 Q1/Q2 不要混淆。

| U5 输出位 / 脚 | 控制网络 | 栅极串阻 / 下拉 | MOS | 外部网络 |
| --- | --- | --- | --- | --- |
| bit0 Q0 / 15 | `UP_EL_DRV` | R10 100Ω / R14 100kΩ | Q1 AO3400A | `UP_EL` |
| bit1 Q1 / 1 | `DOWN_EL_DRV` | R11 100Ω / R15 100kΩ | Q2 AO3400A | `DOWN_EL` |
| bit2 Q2 / 2 | `CW_AZ_DRV` | R12 100Ω / R16 100kΩ | Q3 AO3400A | `CW_AZ` |
| bit3 Q3 / 3 | `CCW_AZ_DRV` | R13 100Ω / R17 100kΩ | Q4 AO3400A | `CCW_AZ` |
| bit4 Q4 / 4 | `W5500_RST` | 直接连接 U6 nRESET（8） | — | 0 复位，1 释放 |
| bit5～7 | 未接 | — | — | 必须写 0 |

MOS 源极接 GND、漏极接外部方向线：U5 输出 1 → MOS 导通 → 外部线被拉低 → 对应方向有效；输出 0 → MOS 截止 → 外部由控制箱决定空闲电位。本板不会主动输出 5V。AO3400A 使用 3.3V 逻辑驱动；验收时测量实际控制线电流及导通低电平。

驱动层只接受“方位停止/CW/CCW、仰角停止/UP/DOWN”枚举，不允许上层直接写四个位。任何时候禁止 bit0 与 bit1 同时为 1，或 bit2 与 bit3 同时为 1；两轴不同方向可以同时动作。反转时先清除该轴两位，再等待经转台验证的换向间隔，最后置新方向。停止必须清方向位，不能只把 PWM 降到 0。

### 2.4 两路角度：电阻分压、滤波、ADC1

| 轴 | 输入与上臂 | 下臂 | ADC 前串阻及对地电容 | MCU |
| --- | --- | --- | --- | --- |
| AZ | `ANGLE_AZ` → R18 4.7kΩ | R22 3kΩ | R20 220Ω；C22 1µF ∥ C23 1nF | GPIO1 / ADC1_CH1 |
| EL | `ANGLE_EL` → R19 4.7kΩ | R23 3kΩ | R21 220Ω；C24 1µF ∥ C25 1nF | GPIO0 / ADC1_CH0 |

忽略外部源阻抗、ADC 负载和器件误差的标称关系为：

```text
k = 3k / (4.7k + 3k) = 0.389610
Vadc = Vfeedback × k
Vfeedback = Vadc × 2.566667
外部满量程 4.5V → ADC 约 1.753V
Rth = (4.7k ∥ 3k) + 220Ω ≈ 2.051kΩ
τ ≈ Rth × 1.001µF ≈ 2.054ms；单极点近似 fc ≈ 77.5Hz
```

每路分压本身约给控制箱带来 7.7kΩ 直流负载，应在**接上本板后**校准，不能直接套用悬空测量的电位器刻度。ADC 选 ADC1，使用覆盖上述输入的衰减档并调用对应 IDF 的校准驱动；C3 最高衰减档的标称有效范围约 0～2.5V，不应把 3.3V GPIO 供电当 ADC 满量程，也不能使用 `raw / 4095 × 3.3` 直接换算。

建议初始采样预算为每轴 200 samples/s、控制周期 20ms，使用有界去尖峰/平均。固件自动使用芯片出厂校准数据，将各 ADC 通道的原始计数转换为电压；用户不需要输入 ADC 修正参数。

两路反馈统一以外部 4.5V、分压后约 1.753V 为满量程。方位与仰角独立采样、独立保存零点：

| 轴 | 输入 | 固定换算量程 | 零点保存 | 满量程调整 |
| --- | --- | --- | --- | --- |
| 方位 AZ | GPIO1 / ADC1_CH1 | 4.5V 对应 450° | `O` 后确认，保存 `V0_AZ` | `F` 显示角度，调整方位反馈电位器至 450° |
| 仰角 EL | GPIO0 / ADC1_CH0 | 4.5V 对应 180° | `O2` 后确认，保存 `V0_EL` | `F2` 显示角度，调整仰角反馈电位器至 180° |

角度随反馈电压增加。两轴使用相同形式的换算：

```text
θ_axis = θ_FS_axis × (Vadc_axis − V0_axis) / (V_FS_axis − V0_axis)
```

`Vadc_axis` 为该通道经芯片出厂校准修正后的 ADC 引脚电压；两轴的 `V_FS_axis` 均固定为 `4.5V × 3 / (4.7 + 3)`，约 1.753V。`θ_FS_axis` 分别为方位 450°、仰角 180°；`V0_axis` 分别由 `O/O2` 保存。采样或有效跨度异常时拒绝保存，保留旧零点。用户接上本板后通过 `O/O2` 和 `F/F2` 完成调整，无需额外数字两点标定。P36/P45/Z 只改变方位显示映射，不改变反馈换算和行程限制。

R18～R23 与电容不构成隔离或完整过压保护；图中没有独立角度输入 TVS/精密钳位。断线可能表现为近 0V，恰与有效端点相似，不能只靠一次低读数识别断线。应结合越界、冻结、变化方向及运动超时停机，且明确无法在所有静止状态下可靠识别断线。

### 2.5 调速：PWM → 有负载低通 → 非反相放大

完整路径为 `GPIO20 SPEED_PWM` → R28 10kΩ → 滤波节点（C35 1µF、R31 100kΩ 对地）→ U8 LM358 的 1IN+（3）。1OUT（1）经 R24 5.1kΩ / R25 10kΩ 构成非反相负反馈，输出再经 R26 100Ω 到外部 `SPEED`。

R31 不仅是掉电下拉，还会与 R28 形成直流分压，不能漏算：

```text
D = PWM 占空比，0 ≤ D ≤ 1
Vfilter ≈ 3.3 × D × 100k / (10k + 100k) = 3.000 × D V
放大倍数 G = 1 + 5.1k / 10k = 1.51
Vopamp ≈ 4.530 × D V
τ = (10k ∥ 100k) × 1µF ≈ 9.09ms；fc ≈ 17.5Hz
外部 Vspeed ≈ Vopamp − Iload × 100Ω，另受器件和电源误差影响
```

调速输出的标称空载范围约 0～4.53V。`X1`～`X4` 映射到开发验收时确定的四档 PWM 占空比。只有方位可调速，仰角由方向控制。

U7 LM2665 从板上 `5V` 经 C31 电荷泵倍压，D9 SS34 为启动通路，C29/C30 输入去耦、C32 输出储能；经 R27 10Ω 与 C33 10µF、C34 100nF 滤波后形成 `9V_AUX`，供 U8 第 8 脚，U8 第 4 脚接地，C26 为去耦。`9V_AUX` 是网络名，不是稳压 9.000V 保证。升压给 LM358 提供输出摆幅余量，不意味着 SPEED 输出 9V。

U8 第二路：R30/R29 各 10kΩ 把 3.3V 分成约 1.65V，送 2IN+（5），2OUT（7）反馈 2IN−（6），构成未外接负载的跟随器；没有接至 SPEED 或 ADC，不能误当反馈测量通道。

PWM 使用 LEDC 硬件输出，建议从 20kHz、10bit 开始验证；平均值按可实现的满占空比处理，核对 API 的计数上限，不能把超范围计数写入定时器。滤波约 5τ（45ms）才接近稳定，切档及接近目标时应考虑这个延迟。运放输出下限、纹波、负载、四档速度、近目标减速均需带控制箱实测。现板没有 SPEED 电压反馈，软件无法确认实际输出是否到达设定值。

### 2.6 W5500 与 74HC595 共用 SPI 的关键条件

GPIO4 MOSI 同时连 U6 MOSI（3）与 U5 DS（14），GPIO3 SCLK 同时连 U6 SCLK（4）与 U5 SHCP（11）；GPIO5 接 U6 MISO（7）、GPIO8 接 nSS（5）、GPIO10 接 nINT（6），GPIO2 接 U5 STCP（12）。GPIO8 由 R1 10kΩ 上拉，GPIO2 由 R4 10kΩ 上拉。

以太网传输必然改变 595 的**移位寄存器**，但只要不产生 STCP 上升沿，595 的**输出锁存器**就保持不变。 每次更新输出必须重新发送完整 shadow byte，然后锁存；不能以为上次移位内容还在。

实现时将 W5500 与一个“无 CS 的 595 SPI device”注册到同一个硬件 SPI host；595 使用 mode 0、MSB first，让最后移入的 8bit 对应 Q7～Q0。595 输出更新必须从总线 acquire 开始，保证 W5500 CS 为高，发送完整字节，等待传输完成，产生一次 STCP 低→高→低，直到锁存完成才 release。锁只覆盖发送、不覆盖锁存，会被以太网事务插入并把网络数据锁存成电机方向。

共享线上 U5 也会看到每一个以太网时钟，因此 SPI 频率不能只按 W5500 上限选取；必须核对 74HC595 在实际 3.3V、温度和负载条件下的时序，并取两者及板级信号完整性允许的较低值。禁止默认将 W5500 的最高 SPI 频率直接用于本板。

禁止在以太网运行时临时用 GPIO bit-bang 接管 MOSI/SCLK，也禁止两个互不相干的 mutex 各管一半。所有 shadow byte 更新由同一个输出管理器串行提交，W5500 复位也经它修改 bit4，并保留四路方向；普通网络恢复不得意外拉动电机。停止事件优先于后续网络事务，总线超时必须上报故障。

U6 nRESET 由扩展位而非 GPIO 控制：通用 Ethernet 驱动应关闭不存在的直接 reset GPIO，在驱动探测前由输出管理器产生符合 W5500 手册的复位脉冲及恢复等待；运行中的硬复位需协调停止驱动任务/收包和总线访问。不可把 GPIO2 交给 W5500 reset 配置。

### 2.7 供电、上电与复位的硬件边界

DC1、USB1 VBUS、USB2 VBUS 分别有 C1/C2/C3、D3/D4/D5 SMBJ6.5CA，随后经 D6/D7/D8 SS34 二极管汇到板上 `5V`；U1 AMS1117-3.3 生成 3.3V。板上 `5V` 受二极管压降及供电负载影响，不等于某 USB 口的实测 5.000V。DC1 没有 12V→5V 降压级；不能沿用原版 GS-232B 的 12V 适配器。Wi-Fi 发射与 W5500 同时工作时要检查 3.3V 峰值、1117 压差及发热、9V_AUX 的负载和纹波。

U5 OE# 的电路是 **C20 1µF 接 3.3V、R6 1MΩ 接 GND**：上电跳变使 OE# 暂时偏高，随后经 R6 回落，标称时间常数 1s。它不是 MCU 可以控制的安全使能，也不是“固定 1 秒后”精确定时；慢上电、短暂掉电和复位都不能据此保证关断。MR# 仅经 R7 10kΩ 上拉，既没有连接 EN，也不能假定锁存器上电内容为零；即便把 MR# 拉低，也要注意它清的是移位寄存器而非直接清输出锁存器。

启动阶段应尽早在 nSS 高、STCP 可控时锁存 `0x00`（四路停且 W5500 保持复位），PWM=0；满足复位时间后写 `0x10` 释放 W5500，再初始化网络及 ADC。只有输出初始化完成，待使用轴的零点记录、固定换算参数及限位有效，才进入允许运动状态；不等待用户提交额外满量程采样点。

**硬件未保证 MCU 复位/卡死即停机**：U5 独立供电时可能保留之前的运动锁存状态；GPIO2 上拉还可能在复位时产生非预期 STCP 上升沿，锁存最后一段 SPI 数据。R14～R17 只在 U5 高阻时把门极拉低，不能压过 U5 的高电平输出；软件看门狗也无法保证 ROM/下载/JTAG 暂停期间及时清零。后续硬件应评估默认禁用、受复位/硬件看门狗支配的 OE# 或输出使能，并核对启动绑带 GPIO2/8/9。没有这类改动前，文档只能承诺“应用正常运行时的停机逻辑”，不能承诺硬件失效安全。

## 3. 官方 GS-232B 的实现范围与兼容边界

### 3.1 完整命令范围

固件必须实现以下全部命令组、响应格式和交互过程：

| 组别 | 必须覆盖 |
| --- | --- |
| 手动与停止 | `R L A U D E S`；两轴可同时动作；停止优先。 |
| 单点定位与速度 | `Maaa`、`Waaa eee`、`X1`～`X4`；约距目标 15° 的减速语义，最终曲线需实测。 |
| 查询 | `C B C2 N`；保留三位角度和 `N` 的四位字段。 |
| 帮助、显示、持久化 | `H H2 H3 P36 P45 Z`；模式掉电保留。 |
| 长序列 | `Msss ...` 最多 3800 个方位点；`Wsss ...` 最多 1900 对；先到第一点再等待 `T`，`N` 查进度，`S` 清除。 |
| 零点交互 | `O O2` → 请求确认 → 同一会话 `Y<CR>` → 保存及完成输出。 |
| 满量程交互 | `F F2` 持续显示读数，单独 `CR` 退出；不能擅自改成“采样当前点并保存”的命令。 |
| 字节层 | 大小写命令、CR 结束、不回显、官方响应行尾及错误行为、上电连接提示。 |

角度校准使用 `O/O2` 保存两轴零点，通过 `F/F2` 显示并调整外部反馈电位器。满量程电压固定为 4.5V；方位范围为 0～450°，仰角范围为 0～180°。P36/P45/Z 只改变方位显示映射，保留重叠行程。

错误标记空格、帮助全文、校准提示、`N` 起始序号、`T` 首次切换时刻、M/W 混用覆盖顺序均纳入协议验收。控制权和掉线停机属于本项目扩展，单会话正常操作遵循官方语义。

### 3.2 UART1 串口策略

默认 8N1、无硬件流控；工厂回退波特率 9600。官方 1200/2400/4800/9600 和约 15 秒开机 CR 匹配过程列入设计目标：在 UART1 RX 上测量连续 CR 的位宽、验证多个完整字符，再切换波特率和持久化；超时用上次确认的波特率并输出一次 `Connect OK`。具体检测外设/API 要依照工程最终锁定的 C3 IDF 版本验证，不能直接使用 UART0 专有能力，也不能靠轮询四种波特率声称已实现可靠自动匹配。

GS 上位机必须关闭 CTS/RTS；官方要求的 CTS 流控是本板无法兑现的物理差异。用足够的 RX 缓冲、专用接收任务、增量解析和有界发送弥补吞吐，但不宣称等价硬件流控。`monitor_speed=115200` 仅是现有 PlatformIO 监视器参数，不是 UART1 的协议波特率定义；原生 USB Serial/JTAG 也不由此获得 UART1 的串口电气时序。

发送端使用 CR；项目容错可吞掉紧接 CR 的一个 LF，不能把单独 LF 当命令结束。错误码与行尾沿用 GS 路径，不插入日志、`OK`、JSON、所有权通知或 Wi-Fi 状态文本。上电 `Connect OK` 仅出现一次对应连接流程；不能周期重发干扰控制程序。

### 3.3 最大序列与边界处理

合法最大长格式的大小约为：`1 字母 + 3 位间隔 + 3800×4 字符参数 + 1 CR = 15205 字节`；W 的 1900 对也是这个量级。因此不能统一用 128/256 字节接收行，也不能每个读事件当一条命令。

建议 UART RX ring 初始预算 32KiB，另用一份最多 7600 字节的 `uint16` 角度 staging 存储（3800 个单角度或 1900 对），边收边严格解析，无需每会话常驻 16KiB 字符串。保留旧序列到新序列校验通过时还需一份最多 7600 字节的 active 存储，不能漏算双缓冲。长序列仅允许当前控制者或取得临时输入预约的会话上传；其他会话仍可查询/停止。输入预约不允许输出运动，在完整 CR、范围与点数校验成功后才执行；串口低速最大合法行可能持续约 127 秒，因此**整行超时不能短于合法发送时间**，使用 2 秒无新增字节超时并限制总长度。

超长、非法字符、UART overflow、分片中断：丢弃当前未完成命令，排空至下一个 CR，返回一次协议错误，禁止执行半个目标或残留后缀。普通语法错误不生成新目标；若活动控制者通道发生确定的字节丢失/overflow，则按通信故障全停，防止漏掉 S 后继续运动。裸 `M`/`W` 仍按基线返回错误并清除对应序列；控制权检查先于该副作用，非控制者不得借错误命令删除他人任务。异常命令的处理顺序和副作用统一纳入协议验收。

## 4. 固件分层与网络实现选择

### 4.1 统一处理链

```text
UART1 / CH340K ──────────┐
W5500 → esp_eth → lwIP ──┼→ 传输适配器 → 每会话字节解析与交互状态
Wi-Fi STA → lwIP ────────┘                        ↓
                                     控制权检查 / 命令调度
                                               ↓
                             唯一运动与序列状态机 ← ADC 采样
                                               ↓
                              唯一输出管理器 → 595 / PWM

配网 SoftAP → 仅管理接口 → 配置服务 → NVS / 网络管理器
原生 USB Serial/JTAG ← 日志、故障、调试；不进入控制处理链
```

UART/HTTP 回调只拷贝有界数据、登记事件，不等待电机到位，不直接驱动 GPIO，不写 Flash。运动循环负责限位、目标、减速、超时；输出管理器统一处理方向、PWM 和 W5500 reset shadow。配置服务在停止状态下处理 NVS 事务。传输适配器持有 `session_id + generation`，文件描述符复用或重连也不能复用旧所有权。普通响应按该会话请求顺序发送；优先停止动作可以先执行，但不能把 S 的响应插到同一会话先前查询回复之前。

### 4.2 W5500 走标准 ESP-IDF 网络栈

选择 W5500 的 ESP-IDF Ethernet MAC/PHY 驱动 + `esp_netif` + lwIP，与 Wi-Fi 共用标准 sockets 和 HTTP/WebSocket 服务。不另用 WIZnet 硬件 TCP socket 库建立另一套网络栈；W5500 在此作为以太网接口使用，其“8 个硬件 socket”不直接等于应用的 WebSocket 会话上限。

保留当前 ESP-IDF / PlatformIO 工程结构。`platformio.ini` 固定 `espressif32@8.0.0`，开始实现前应记录实际解析到的 ESP-IDF、W5500 驱动与组件锁定版本，再核对 API/Kconfig。本次不修改依赖、sdkconfig 或构建文件。

W5500 和 Wi-Fi STA 均独立拥有 netif、MAC、IP、DHCP 状态及重连状态，不复制同一 MAC。W5500 MAC 采用芯片基准 MAC 的正式分配/派生途径，确保本设备各接口唯一且重启稳定，不依赖模块预置 MAC。

服务层监听所有已启用接口，或按锁定 IDF 的能力绑定各 netif；应用主动外联的默认路由优先以太网，其次 Wi-Fi。默认路由切换不迁移已有 TCP 连接，也不能保证连接不断。 已建立会话记录其本地 IP/入站接口，只因自身接口失效而断开，不因为另一接口重连就重启整个服务器。

以太网和 Wi-Fi 接同一子网是必须测试的部署场景：要核对响应出口、ARP、地址冲突及 AP 客户端隔离，不能把 route priority 当作连接绑定。若当前 lwIP 出现从另一网卡回包，应通过该版本支持的 socket/interface binding 保持出口，必要时使用按 netif 的监听/会话适配层；未经双网同网段测试不能承诺该场景通过。SoftAP 子网必须避开两个上联网段。

### 4.3 HTTP 与 WebSocket

使用 ESP-IDF `esp_http_server` 的 WebSocket 能力，开启对应配置；HTTP 仅用于 Upgrade 和管理接口，不提供网页，不启用 TLS/HTTPS。

| 项目 | 本项目约定 |
| --- | --- |
| 控制入口 | `ws://<接口IPv4>/ws/gs232b`，TCP 80。以太网和 Wi-Fi 相同路径、相同协议。 |
| GS 负载 | 原始 GS 字节；接受 ASCII Text 或 Binary 数据消息，输出统一为 Binary，逐字节保留原行尾；不套 JSON。 |
| 应用分包 | CR 才是命令边界。一条命令可跨多条 WS 消息；一条消息可含多条命令。不得自动加 CR。 |
| RFC 分片 | 适配层正确处理 continuation；Ping/Pong 不进入 GS 输入缓冲。控制帧可以穿插，且不充当 CR。 |
| 初始边界 | 完成 Upgrade 后发一次 `Connect OK` 连接提示（项目对网络会话的约定），清空该会话解析状态，不等待串口自动波特率窗口。 |
| 输入容量 | 单 WS 数据帧/消息接受到 16KiB 的有界负载；按小块解析，整个合法 GS 长行上限 15205 字节；不依赖客户端一次装入最大行。 |
| 资源上限 | 默认最多 4 个网络控制连接（以太网和 Wi-Fi 合计），另有 1 个 UART 会话；配网管理另留少量连接预算。超限拒绝新连接，不驱逐活动控制者。 |
| 活性 | 网络每 5 秒 Ping，连续 3 次无 Pong/读写失败判失联；TCP keepalive 辅助。Pong 表示传输活着，不表示上位机策略健康。 |
| 发送 | 每会话有界 TX 队列（初始 4KiB，帮助输出可分块），按序发送；慢客户端超时关闭。当前控制者关闭则触发停止。 |

以上容量、5/15 秒及队列大小均是可调的设计起点，需在开启 Wi-Fi 与 Ethernet 后测量堆余量与最坏延迟。不能让一个大 WS 帧、帮助输出或阻塞发送占住运动循环。超过限制按适合的 WebSocket close code（例如过大负载 1009、策略 1008、内部错误 1011）或 GS 解析错误处理；传输断开后不补发断线前的移动指令。

普通命令入口应限速并使用有界队列（初始每会话最多 8 个待处理请求），保留独立停止事件槽；资源耗尽不能让只读洪泛饿死运动检查。socket 总数还需计入 HTTP 服务内部句柄、管理连接、DHCP/DNS 等实际栈资源，不把“4 个控制客户端”直接当作 lwIP 全部 socket 配额。

三路响应只发回来源会话；`C/B/C2/N` 可查询共享实际状态。`F/F2` 的周期校准读数只发给发起会话。状态变化不会往其他普通 GS 会话主动广播，否则旧上位机会把异步消息当成查询回复。

## 5. 并发连接与唯一控制权

### 5.1 选择与原因

采用“**同时连接、同时只读、单一会话写控制**”。单纯按 USB/网口谁先连接来屏蔽其他接口，会让空闲连接占着设备，也妨碍通过 UART 修复网络；三个入口无锁共同写则会互相覆盖方向、目标、序列和校准确认。

所有权单位是会话，不是“整个以太网”或“整个 Wi-Fi”，也不是单条命令。方位与仰角共用一次控制权；本版不把两轴分给不同用户，以免 `W/S/T` 的语义分裂。

| 命令类别 | 非控制者可否执行 | 控制权行为 |
| --- | --- | --- |
| `C B C2 N H H2 H3`、扩展只读状态 | 可 | 不取得控制权；每个会话各自收响应。 |
| `R L U D M W Xn T` | 无控制者时可自动取得；已有他人则拒绝 | 所有运动/速度/序列修改经同一检查。 |
| `O O2 F F2`、`P36 P45 Z` | 需控制权且满足停机等前置条件 | 校准交互只接受发起会话的输入。 |
| `A E S` | 可（已获准连接的会话） | 全局安全例外；按下文执行，不等待普通命令队列。 |
| 网络/持久化配置写入 | 需管理授权，且无活动运动/序列/校准 | 与运动所有权分开检查，事务持有配置锁。 |

普通 GS 命令因忙或无权被拒绝时，只返回选定的 GS 错误标记，不加入 `BUSY` 字样；扩展状态可查询占用者和具体原因。

### 5.2 取得、保持、释放与停止

- 没有控制者时，第一条合法写控制命令自动取得；只读连接无需发送扩展命令才能使用。长行上传可先预约解析资源，CR 校验完成前不移动，超时或错误释放预约。
- 活动运动、等待 `T` 的已加载序列、运行序列、校准交互期间均保持控制权；不得在序列 999 秒等待间隔中因“没有串口字节”释放。
- 两轴停止、无待运行序列、无交互时，空闲 2 秒后自动释放；控制者也可用 `!OWNER RELEASE` 显式释放，但必须先停止并清理任务。
- `S` 在所有正常解析/交互状态下作为全停优先命令：两轴停、清序列、取消校准与未执行目标、清暂存动作、撤销所有权。它不清除已保存的校准、显示模式或网络配置。
- `A/E` 立即停止对应轴，并取消定时序列，避免下个时刻重新启动该轴；另一轴已经接受的单点/手动动作可继续，当前所有权保留。该并发安全约定需在兼容矩阵中单列。
- 全停、控制者掉线或更换控制者时递增 command epoch。队列中的命令携带旧 epoch，一律作废；否则优先处理 S 后，队列中旧 R 可能再次启动。尚未接收完整的旧命令行也须失效，并丢弃到下一个 CR，不能把上传序列的剩余字节当成新命令继续执行。

停止识别以**完整、独立的 CR 命令行**为准，不能把数字序列、SSID 或任意 payload 中的字母 S 当急停；UART 帧损坏或未送达 CR 时无法保证收到停止。紧急事件通道独立于普通队列，长行解析必须持续让出 CPU。网络停止不是硬件急停，仍受链路和当前硬件结构约束。

### 5.3 断线、交互与 UART 的特殊情况

活动网络控制者收到 Close、读写失败、心跳超时、所属接口 link/IP 失效时：停止两轴，清除序列/临时校准/输入缓冲，撤销所有权；重新连接必须新建会话，不自动续跑。其他接口的控制者不受该网络故障影响。

UART 无 CTS/DTR/RTS 连线，拔 USB2 后 MCU 不一定能感知。因此 UART 默认保持官方的“手动转动直到停止命令/限位”语义，不虚构串口断线检测；用每轴最大连续运行时间、反馈异常检测和机械限位兜底。扩展协议可让主动支持的客户端启用命令看门狗并定期心跳；默认不开启会让老 GS 上位机意外停止的短租约。运动超时应按控制箱实测全行程时间配置，不能把 15 秒网络心跳或 2 秒空闲释放直接套到 UART 手动转动。

`O/O2` 的 Y/N、`F/F2` 的空行退出只属于发起会话；旁路会话的 CR 不能退出校准。正常已连接的非控制者始终可发送 S。交互无有效输入 60 秒退出且不提交新校准；F/F2 周期输出不算用户活动。

## 6. 网络配置与无按键配网

### 6.1 常用实践与本项目取舍

主维护通道选择 **UART1 文本扩展命令 + NVS 持久化**：不依赖网络已经工作、无需装前端，也便于出厂和救援。SoftAP 是无线入口，使用同一配置服务的设备端 API；不引入 SmartConfig、云账号或另一个 BLE 配网协议栈。ESP-IDF 本身支持 SoftAP/配网管理基础能力，但本设计不要求直接套用其官方手机 App 或 protobuf 协议。

设备无用户可按的 BOOT/RST，配置路径固定为：

| 情况 | 设备行为与操作路径 |
| --- | --- |
| 首次启动、没有有效 Wi-Fi 凭据 | W5500 同时尝试 DHCP；自动开受保护的配网 SoftAP，UART1 始终可用。 |
| 已保存有效凭据 | Wi-Fi STA 自动连接，W5500 按各自设置启动；默认不常开 SoftAP。 |
| Wi-Fi 临时失联 | STA 有界退避重连，ETH 及 UART1 照常运行；不因一次断线清除凭据或自动创建开放 AP。 |
| 需要更换 Wi-Fi | UART1 或已授权的可达管理会话执行 `!PROV START`，或者直接以事务更新凭据。 |
| 两个网络都不可达 | 通过 USB2/CH340K 的 UART1 查询、开启配网或恢复网络；不要求按隐藏按钮。 |
| 全部网络配置需要恢复 | UART1 发送限定范围的网络重置；保留转台校准和机械限位。 |

首次自动配网窗口初始设为 10 分钟，超时关闭 SoftAP、保留 UART；未配置设备下次上电再进入窗口。已配置设备只有管理命令才开窗口，失败重连不自动暴露长期配网入口。日常操作不依赖拔电重启；此处上电只是无配置设备的初始状态。

SoftAP SSID 建议 `GS232B-<唯一后缀>`，使用每设备独立 WPA2 密码，出厂记录/标签或 UART1 `!PROV STATUS` 可取得，不用全机通用密码。若生产阶段尚未建立标签流程，UART1 是获得该设备配网凭据的确定路径。配网密码、Wi-Fi 密码和管理 token 不输出到 USB 调试日志，不从普通网络状态查询返回。

SoftAP 默认使用 `192.168.4.1/24`，若与 ETH/STA 子网冲突则选不同私网；`!PROV STATUS` 返回实际地址。AP 只开放管理 WebSocket `/ws/manage`，不接受旋转控制；无 NAT/路由转发、无网页/portal/DNS 劫持。建立 Wi-Fi 配置后以 AP+STA 模式验证，注意单无线电共用信道可能使 AP 客户端短暂断开；试运行未确认前仍保留有界管理恢复窗口。

`/ws/manage` 的负载也使用第 7 节扩展命令，不承载普通 GS 运动命令。未来的任意 WS 调试工具或上位机都能接入；本次交付不包含这些工具。配网窗口是管理访问条件，不授予电机控制权。

### 6.2 W5500 DHCP 与固定 IPv4

ETH 首选 DHCP。状态区分 `LINK_DOWN / LINK_UP_NO_IP / DHCP_WAIT / READY / ERROR`；链路连上不等于已获 IP。DHCP 获取、更新租约和失败重试不能阻塞控制；租约变化导致本接口已有 TCP 会话失效时，按控制者掉线规则停机。

固定 IPv4 配置包括 `address / netmask / gateway / dns1 / dns2`。应用固定地址前先停止该 netif 的 DHCP client，再设置 IP/DNS；切回 DHCP 先移除旧的静态运行状态，再启动 DHCP。不同时保留静态地址和活动 DHCP client。

检查 IPv4 解析、连续掩码、非网络/广播主机地址，以及非零网关与本地地址同网段；独立直连网段允许网关 `0.0.0.0`。DNS 可空，本地 WS 不依赖 DNS。遇到地址冲突标为错误并回滚试运行，不在 DHCP 失败时偷偷退到某个固定 IP，以免制造地址冲突。

ETH/Wi-Fi 运行状态分别返回 IP、mask、gateway、DNS、MAC、link/连接状态；配置值和 DHCP 当前租约必须分字段，不能把租到的 IP 当成保存的静态配置。W5500 Lite 的模块版本、电源、复位和 SPI 时序纳入板级验收。

### 6.3 Wi-Fi STA

首版支持 2.4GHz、WPA2-Personal；不承诺企业 802.1X、5GHz 或未验证的 WPA3 组合。持久化 SSID、密码、启用状态，STA 默认 DHCP；预留独立的固定 IPv4 配置结构，以便将来扩展，但不把 ETH 静态配置误用于 Wi-Fi。

SSID 按解码后的 UTF-8 字节计最长 32 字节，不把字符数当字节数；首版密码规则限定受支持的 WPA2 形式（8～63 字节口令或经驱动验证的 64 位十六进制 PSK）。JSON 中的引号、反斜杠、中文必须通过正常字符串转义传输；不能按空格拆 SSID/密码。是否允许开放目标网络必须是显式配置选择，不能把缺密码意外当作开放网络。

重连采用有界指数退避（例如 1/2/4/8/16/30 秒上限），记录失败原因，网络管理任务只调整自己的 netif。Wi-Fi 连接成功不会自动停用 Ethernet，Ethernet 成功也不自动关闭 Wi-Fi；两者均可接受控制连接。

### 6.4 应用配置必须能回滚

配置分 **已确认 active、会话 candidate、试运行 trial**。先在 RAM 中修改候选并校验，只有两轴停止、无序列、无校准、无他人配置事务时才能应用；不能为应用配置暗中切断另一个控制者。操作者应先发 S 并确认停止。

`APPLY` 返回试运行 ID 后由网络管理任务应用，默认 120 秒内等待 `CONFIRM`；断开旧连接是预期情况，返回响应不等于新链路已经验证。重新连到新地址，用试运行 ID 确认；UART1 也可确认。DHCP 不要求存在外网/互联网，只要求预期本地链路可用。失败、超时、显式放弃或试运行中掉电，都恢复上一个已确认配置。

NVS 使用带 schema version、revision 及校验的整体配置记录；已确认与候选分开，确认成功才切换 active。跨多个 NVS key 的业务原子性需要自行设计并做断电测试，不能把每个字段单独 `commit` 视为整体事务。 密码查询只返回 `password_set`，修改时缺省表示保留，显式清除需专门字段；避免用脱敏字符串 `***` 覆盖真实密码。

网络配置、GS 显示设置、每轴零点记录使用不同逻辑域；电气换算、行程限制和调速参数固定在固件中。网络恢复命令只能清除网络域；任何擦除全部配置的动作必须另设显式命令和确认过程，不能复用“配网失败”或“启动多次”作为条件。

## 7. 扩展命令契约

### 7.1 命名空间、返回与授权

命令采用 `!DOMAIN ACTION [JSON对象]<CR>`，与官方单字母命令分离。扩展命令不改变普通 GS 响应：一条完成的扩展请求恰好返回一行 `!<JSON对象>\r\n`，例如 `!{"ok":true,"cmd":"NET GET","data":{...}}\r\n`；错误使用 `ok:false`、稳定 `error` 字段和可选 `detail`。不在普通 GS 通道推送异步事件，以状态轮询读取配置进度。

扩展行初始上限 2048 字节，JSON 禁止原始 CR/LF 控制字符，允许 `\uXXXX` 等合法转义。定义 `INVALID_ARGUMENT / BUSY / NOT_OWNER / NOT_AUTHORIZED / NOT_READY / CONFLICT / TIMEOUT / HARDWARE_FAULT` 等稳定错误；普通 GS 命令仍用其自身错误标记，不用这些 JSON 错误代替。

UART1 视为本地管理入口。普通网络 GS 连接初版面向可信局域网；只读信息与运动所有权不等于管理权限。STA/ETH 上的网络配置扩展写入默认禁用，若启用则需设备独立 token，经 `!SESSION AUTH` 显式建立会话管理身份；不把 token 放入 URL 查询串。官方 `O/O2/F/F2` 仍按控制权及停机规则执行，不要求另行管理认证。SoftAP 管理入口只在受保护的配网窗口开放，凭独立 AP 密码进入后仅可配置网络，不可改机械限位、校准或开始运动。

HTTP/WS 无 TLS，管理 token 不能提供链路加密；无线/有线非可信网络不属于本设计部署范围。可见的浏览器 Origin 要有明确允许策略，避免任意网页跨站发起局域网控制；无 Origin 的受支持原生客户端单独处理。这里不增加 HTTPS、云鉴权或前端实现。

### 7.2 首版设备端命令

| 命令 | 用途与关键规则 |
| --- | --- |
| `!SYS INFO` | 版本、板型、能力、配置 schema、三个入口可用性；不暴露密码。 |
| `!NET GET` | 已确认配置、实际运行状态、candidate/trial 摘要；密码只返回是否已设。 |
| `!ADMIN ENABLE` / `!ADMIN DISABLE` | 仅 UART1；启用时生成至少 128bit 随机 token，仅此响应返回一次；只保存校验材料；禁用/换 key 撤销现有网络管理身份，不删除运动校准。 |
| `!SESSION AUTH {"token":"..."}` | 已启用的 ETH/STA 管理会话认证；失败不获得权限，不回显 token。 |
| `!CFG BEGIN` | 建立单一候选事务并返回 ID；复制 active 到 RAM；其他配置写事务返回 CONFLICT。 |
| `!NET SET {...}` | 仅修改当前候选的 ETH/Wi-Fi 字段；字段校验、凭据脱敏、未提供的字段保留。 |
| `!CFG CHECK` | 完整校验，返回需改变的接口及错误；不触发网络切换。 |
| `!CFG APPLY {"trial_s":120}` | 停止状态下应用候选；30～600 秒可选，默认 120；返回 trial ID。 |
| `!CFG STATUS` | 查询 active revision、候选/试运行 ID、deadline 和各链路验证结果。 |
| `!CFG CONFIRM {"trial_id":42}` | 在新管理会话或 UART1 确认匹配的试运行；成功后持久化。ID 42 仅为示例。 |
| `!CFG ABORT` | 丢弃候选；若正在 trial 则恢复旧 active。 |
| `!PROV START {"timeout_s":600}` | 无运动等冲突时，启动有界 SoftAP；若已开启则返回现状，不能无限延长他人的试运行。 |
| `!PROV STATUS` / `!PROV STOP` | 查窗口和地址 / 关闭 AP；密码仅 UART1 可查；STOP 在未确认 trial 中不得破坏恢复路径。 |
| `!NET RESET {"confirm":"NETWORK_ONLY"}` | 仅 UART1、停止状态；清除网络域并进入未配网状态，不依赖按钮，不清机械配置。 |
| `!OWNER GET` | 返回当前控制会话、传输类型、当前模式及占用原因，不泄露认证凭据。 |
| `!OWNER TAKE` / `!OWNER RELEASE` | 空闲时显式申请 / 清理后释放；不抢占现有控制者。普通 GS 不必使用它们。 |
| `!SESSION WATCHDOG {"timeout_ms":...}` / `!SESSION PING` | 控制者自愿启用应用命令看门狗及续期，0 表示关闭；与 WS Ping/Pong 分开，生效范围仅当前会话。 |
| `!MOTION STATUS` | 实际角度、原始/校准 ADC、方向、目标、限位、故障和数据有效性；不是运动完成异步推送。 |
| `!FAULT CLEAR` | 停机并确认故障条件消失后显式解除锁定；不会自动重跑旧目标。 |

`!SESSION WATCHDOG` 超时必须执行与控制者失联相同的全停及任务清理；仅当前控制者成功的完整命令或 `!SESSION PING` 续期，旁路查询、无效命令和 WS Pong 均不能续期。建议可设范围 1000～600000ms，默认 0；上传长序列时客户端必须选足以覆盖合法低速传输的时限，或在停机时关闭此可选功能。

未 APPLY 的配置事务在发起会话关闭或 60 秒没有配置请求时丢弃；一旦进入 trial，计时和回滚独立于原会话，新授权连接/UART1 可凭 ID 接续确认。重复 CONFIRM 相同已确认 trial 可幂等返回结果；旧 ID、并发 revision 改动或错误 ID 必须拒绝。活动事务不能阻止读取状态或发送 S。

目标容差、换向停顿、最大连续运行时间及四档 PWM 参数在开发验收时确定，固定在固件中。用户通过 `O/O2` 保存零点，使用 `F/F2` 配合外部电位器调整满量程。缺少有效零点或采样反馈时允许查询与校准，但禁止软件发起运动；准备位置由控制箱手动完成。

### 7.3 无前端的操作示例

以下只是协议示例，占位 IP/SSID/密码不是设备预置数据。每行实际发送 CR；响应中的 trial ID 以设备返回为准。

USB2 / UART1 设置 ETH 固定 IPv4：

```text
!CFG BEGIN
!NET SET {"eth":{"mode":"static","address":"192.168.10.50","netmask":"255.255.255.0","gateway":"192.168.10.1","dns1":"192.168.10.1"}}
!CFG CHECK
!CFG APPLY {"trial_s":120}
!CFG STATUS
!CFG CONFIRM {"trial_id":42}
```

切回 DHCP：在新事务内发送 `!NET SET {"eth":{"mode":"dhcp"}}`，再 CHECK/APPLY/CONFIRM；运行 IP 以 `!NET GET` 为准。

USB2 / UART1 配置 Wi-Fi，或者在已开的 SoftAP 管理 WS 内配置：

```text
!CFG BEGIN
!NET SET {"wifi":{"enabled":true,"ssid":"YOUR_SSID","password":"YOUR_PASSWORD","security":"wpa2-personal"}}
!CFG CHECK
!CFG APPLY {"trial_s":120}
!CFG STATUS
!CFG CONFIRM {"trial_id":42}
```

手动开始无线配网只需通过 UART1 发 `!PROV START`、查询 `!PROV STATUS`，再使用外部 WS 客户端连接所返回 AP 地址的 `/ws/manage`。没有可用网络时也不用 BOOT/RST；错误配置或丢失网络凭据可通过 UART1 重新写入或执行 NETWORK_ONLY 恢复。

## 8. 运动控制与故障处理

每轴至少有 `DISABLED / IDLE / MANUAL / GOTO / REVERSAL_WAIT / FAULT`；定时序列另有 `EMPTY / LOADED_WAIT_T / RUNNING / COMPLETED`，交互校准属于会话状态而不是阻塞式全局终端循环。

位置控制使用零点修正后的角度，检查行程限制、反馈方向和目标可达性，再控制转动、减速及停机。目标容差、连续运行上限、无进展判定和换向间隔在开发测试中确定。

| 事件 | 必须的处理 |
| --- | --- |
| 上电、待使用轴缺少有效零点或限位无效 | 四路停，PWM=0，允许管理、查询及官方校准准备，拒绝运动；不要求用户提供满量程采样点。 |
| 正常到位 | 清该轴方向，更新到位状态；不产生官方未定义的 DONE。 |
| 用户 S、控制者失联 | 清两轴方向与目标、序列和交互，撤销旧 epoch；正常释放控制权。 |
| 越限、运动反馈反向、持续无进展、ADC 明显异常、运行超时 | 立即全停并锁定 FAULT；记录原因；修复后显式 CLEAR，不自动重试旧动作。 |
| SPI 提交失败 | 尝试在可用条件下提交全停，记录输出状态未知；不能因为“已请求停止”就标记物理已停。 |
| Wi-Fi/ETH 重连、DHCP 失败 | 仅处理该网口与所属会话，不阻塞其他接口或运动定时；控制者掉线仍须全停。 |
| 网络配置或 NVS 失败 | 不提交半配置，返回稳定错误，恢复 active；不改机械校准。 |
| MCU watchdog、EN 复位、JTAG 暂停 | 软件无法保证及时清 595；按第 2.7 节列为硬件层限制。 |

长序列用单调时钟调度，不依赖网络时间/NTP；间隔等待期间仍运行反馈和故障检测。定时序列运行时若下一个目标尚未可执行，不得悄悄排出无限过期目标；精确 `T/N` 时序按官方对照结果落定，并测试 999 秒间隔、限位和中途停止。

## 9. 后续实现顺序与验收
