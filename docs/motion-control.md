# 双轴运动控制核心与仿真验收

接口见 [`motion.h`](../include/gs232b/motion.h)。核心代码不依赖 ESP-IDF、动态内存或墙上时钟，已加入固件组件和原生测试构建。当前 `app_main` 仍是构建基线；实际板级 SPI/PWM/ADC 驱动、运动任务和协议命令分发需在后续集成中接入这些接口。

## 状态与动作

每轴独立维护动作和状态，输出统一交给现有输出管理器。一个轴等待换向或正常到位，不阻塞另一轴。

| 状态 | 进入条件及行为 |
| --- | --- |
| `DISABLED` | 设备配置未启用该轴或缺少有效零点，拒绝手动运动和定位。 |
| `IDLE` | 已启用且有有效配置，无动作；启动还要求当前位置有效。 |
| `MANUAL` | 按正/负方向持续运动，直到停止、限位或故障。正方向为 AZ CW / EL UP。 |
| `GOTO` | 根据机械角目标选择方向；进入容差后清除该轴动作和目标，不因位置漂移重新启动。 |
| `REVERSAL_WAIT` | 输出管理器已清该轴方向，等待完整停顿；保留最新动作，不积压旧方向。上电和输出失败恢复后首次使能也遵守等待。 |
| `FAULT` | 任一受监测轴故障时，两轴动作和目标全部撤销，尝试一次强制全停；所有已启用轴锁定，未启用轴仍为 `DISABLED`。 |

`manual`、`goto` 只替换指定轴的动作。双轴 `goto` 先验证全部选中目标、零点和反馈，再一起接纳；失败不接纳部分目标。目标必须是固定机械坐标，显示角到机械角的转换由 `coordinates.h` 完成。禁用 EL 时，协议层应将允许的 `Waaa 000` 转成只选择 AZ 的动作。

`stop` 清除所选轴的动作及目标，不要求反馈或零点有效；全选会强制提交全停。单轴停止保留另一轴动作，同时检查另一轴的安全条件。停止不会解除 FAULT。

## 反馈、安全与调速

启动前及每次 `tick` 都读取采样并执行安全检查。已启用且有有效零点/限位的轴受故障监测：任一轴有动作时，另一受监测轴的反馈失效也导致全停。未启用或缺零点的轴不会阻止另一轴独立工作。

| 条件 | 处理 |
| --- | --- |
| 轴禁用、缺零点、普通采样尚未就绪 | 拒绝该轴启动；缺零点时仍可提供原始采样供校准使用。 |
| 采样无效、超过 100ms、时间来自未来或倒退、采样端口错误 | 运动中锁定 `SAMPLE`；丢弃旧滤波位置。时间戳高水位独立于滤波窗口，清窗不会使倒退采样重新有效。 |
| 电压超过固定满量程、校准后低于零点 | 锁定 `SAMPLE`，即使尚未启动也不接纳异常反馈。 |
| 原始机械位置超出固件限位，或手动运动抵达限位并继续向外 | 锁定 `LIMIT`；不能用滤波滞后遮蔽越限。合法端点定位允许正常到位。 |
| 相对当前实际方向的最远位置，反馈反向达到阈值 | 锁定 `FEEDBACK_DIRECTION`，包括先正常前进再出现反向的情况。 |
| 未取得指定幅度的同向净进展且到达期限 | 锁定 `NO_PROGRESS`；小幅往返抖动不会持续刷新进展计时。 |
| 实际方向连续使能达到最大时间 | 锁定 `RUN_TIMEOUT`。 |
| 输出管理器提交失败或输出未知 | 锁定 `OUTPUT`；尝试一次全停。全停失败保留 `output.known=false`，后续 tick 不自动重试。 |

定位和进展判断使用每轴独立的现有 5 点反馈滤波器；原始电压和位置先检查异常/越限。同一采样时间戳只入窗一次。实际方向改变后重新建窗，避免旧方向的滤波尾迹触发反向故障。

运行/无进展计时从方向实际提交完成后开始；换向等待期间不计入。连续同向的目标替换、重复手动命令、速度更新均不重置计时。使用单调时间差，支持时间原点为零及接近 `UINT64_MAX` 的时间值。

默认配置两轴禁用且零点无效。开发参数为：到位容差 0.5°、减速区 15°、进展阈值 0.1°、反向阈值 1°、无进展 5s、连续运行 300s，AZ 常速/近目标 PWM 为 800/300‰。这些是仿真开发起点，不能作为控制箱实测参数。限位允许在固定 AZ 0～450° / EL 0～180° 内收窄；非法限位或零点配置直接拒绝。

仅 AZ 有速度通道：定位距离不大于减速区时使用 `min(当前速度, 近目标速度)`，因此低速档不会因进入减速区而加速。EL 接口仅支持方向，不承诺仰角 PWM 减速。

## 故障清除与集成约束

`clear_fault` 始终先撤销两轴动作并强制全停，再重新检查受监测轴反馈和限位。输出提交失败或反馈仍异常时保留锁定及首次故障记录；成功后进入 `IDLE` / `DISABLED`，不会重新执行旧手动方向、定位目标或待换向动作。限位处静止可以清除，但新的向外运动会再次触发限位保护。反接、卡滞等静止时不可观测的原因，需由操作者修复后清除。

控制器借用输出管理器的单调时钟，所有调用须由同一任务或同一外部锁串行化。外部仅可串行更新管理器的 W5500 reset；其提交失败后必须立即调用运动 `tick` 锁定故障，再进行其他恢复提交。方向、PWM、换向推进和运动停止由运动层独占。采样端口必须快速返回真实采样时间，不能用读取时间掩盖陈旧数据。

协议/序列所有者应在故障和全局停止事件中同步丢弃旧队列、序列和交互并撤销命令 epoch，避免将旧请求作为新命令再次提交。本运动核心不持有协议队列或会话；这些能力已在独立的[所有权与停止仲裁核心](command-control.md)实现，通过同步执行端口接入。当前仿真周期为 20ms；真实任务周期和参数需结合速度、滤波滞后、模拟 SPEED 响应和最坏调度延迟验证。软件不调度或外设提交失败时，不能据此保证物理停机。

## 仿真验收

模型见 [`motion_sim.h`](../tests/fakes/gs232b/motion_sim.h) / [`motion_sim.c`](../tests/fakes/motion_sim.c)，明确仅用于仿真。它以真实运动核心和输出管理器驱动理想积分器：AZ 满速 10°/s，速度与 PWM 成正比；EL 固定 6°/s，无惯性、负载或背隙。积分后的角度反算为两路 ADC 校准微伏，再经过真实反馈校验、滤波和坐标换算。模型独立检查方向互锁、停顿时长、PWM 和保留位。

运行 `python3 scripts/test.py --host-only`；包含原有回归测试及以下两组仿真测试：

| 测试 | 覆盖 |
| --- | --- |
| [`motion_tests.c`](../tests/host/motion_tests.c) | 六种状态中的正常路径、双轴并行到位、AZ 近目标减速、低速钳制、两端点定位、手动反转、反转中的目标替换、单轴/全局停止、缺零点/无效反馈拒动、双轴原子验证、保留 W5500 reset。 |
| [`motion_fault_tests.c`](../tests/host/motion_fault_tests.c) | 两轴分别反向、卡滞、持续运行超时；重复指令不能延长期限；无效/陈旧/未来/倒退采样、IO 错误、上下电压越界、双向限位及原始位置保护；输出与停机提交连续失败、显式恢复；反转等待中的故障取消；CLEAR 不恢复旧目标、手动方向或待执行反向。 |

上述验收证明软件状态和输出请求行为，不是实机动力学或硬件失效安全验证。固件交叉编译使用 `pio run -e esp32-c3-wroom-02u-n4`。
