# 资源预算与容量边界

记录日期：2026-11-02。下表使用 ESP32-C3 / ESP-IDF 6.1.0 的真实编译参数与 ABI；`scripts/resource_budget.py` 编译不链接的 `tests/budget/resource_layout.c`，以符号长度计算布局，再比对默认固件 ELF 的 `runtime` 符号。主机 `sizeof` 不参与此预算。

```sh
python3 scripts/test.py
# 已有默认固件构建时可单独重算：
python3 scripts/resource_budget.py
```

默认完整测试会运行资源检查；`--host-only` 跳过目标预算，不把主机布局当作替代。JSON 输出位于 `build/resource-budget/budget.json`；板上堆峰值和控制延迟保持 `null`。

## 静态对象

| 对象 | C3 字节数 | 归属与边界 |
| --- | ---: | --- |
| 完整静态 runtime | 175640 | 包含下列所有静态子项及 ADC/ETH/STA/SPI/启动状态，不与子项重复相加。 |
| dispatcher | 52584 | 包含控制请求描述符、序列双缓冲、7 个会话响应/扩展缓存、网络事务/认证/配网状态。 |
| 序列双缓冲 | 15200 | dispatcher 内部；2×3800×uint16，唯一 staging 预约，M 最大 3800 点/W 最大 1900 对。 |
| 请求正文池 | 2048 | app 内部；所有普通请求共用，M/W 只存数字描述符。任一池或描述符上限先到均拒绝新请求。 |
| WS adapter | 102392 | 4 个客户端的所有静态空间，连接数变少不释放/重分配这些数组。 |
| WS 单客户端 | 25568 | 包含 RX 64×288B、TX、行工作区、控制帧、wire、会话/原子状态。 |
| WS RX 槽合计 | 73728 | 4×64×288B；净字节最多 4×16384，额外空间是完整会话键/epoch、长度和 ABI 对齐。 |
| WS TX / 行工作区 | 16384 / 8192 | 各连接 4096B / 2048B。 |
| WS 控制帧 / wire 合计 | 2176 / 1064 | 各连接最多 4 个 125B 控制 payload，wire 数组为 266B。 |
| UART adapter / 行工作区 | 4472 / 2048 | adapter 包含 4096B 软件 TX 和启动捕获状态；驱动 RX/RTOS 队列另行动态分配。 |
| store worker / 其中缓存 | 7680 / 7616 | 7 域×current/previous，共 14 个固定 544B cache；每记录正文最多 534B。 |

探针设置完整 runtime **176KiB（180224B）** 静态上限；当前距离该门槛 4584B。修改会话数、请求数、行工作区或导致 runtime 超出门槛时，构建资源检查失败，必须重新审查预算。此门槛只是本次静态回归边界，不表示板上还有 4584B 堆。

本次默认 ELF 的链接报告：静态 RAM **207700/327680B**，Flash **984974/1048576B**。因此链接静态 RAM 以外的名义空间为 **119980B**；这不是启动后可用堆，也不是最大连续可分配块。SDK 数据、任务和驱动随后仍会占用它。

## 动态队列、缓存与 SDK 边界

| 分配 | 长度/净 payload 预算 | 满额与失败策略 |
| --- | --- | --- |
| UART driver RX | 32768B | 包队列满则保留驱动 ring；硬件/driver 溢出或错误进入丢字节故障、全停/撤权和 CR 重同步。 |
| UART RX 包 | 8×288=2304B | 每轮最多搬 256B、已在入队前盖章，队满不读出再丢弃。 |
| UART 事件 | 32×12=384B | 饱和保守视为丢字节；无无界积压。 |
| 启动 RMT 完成事件 | 1 槽、最多 48 个按值符号 | ISR 覆盖旧项，序号缺口使候选失效；波特率确定后释放。它与运行期队列分开。 |
| ADC 最新样本 | 两个 1 槽，共 48B | 覆盖最新值，慢消费者不阻塞采样、不堆积历史。 |
| ETH/STA SDK 事件 | 各 16×56B，共 1792B | 各轮有界消费，溢出撤销地址与旧会话。 |
| ETH/STA fence | 各 1×8B，共 16B | 完整代次屏障；没有无界确认列表。 |
| ETH/STA 工作请求/结果 | 每接口各 1 槽，共 16B | 忙时返回 BUSY/WOULD_BLOCK，不产生后备链表。 |
| 应用网络/AP 邮箱 | 各 1 槽，共 256B | 覆盖最新完整请求，忙时留存最新值。 |
| NVS 工作请求/完成 | 各 1 槽；请求含最多 534B 记录 | 一次一个同步事务，只在已知全停时等待实际完成；不把超时伪装为取消。 |
| HTTPD work | adapter 最多一个待处理 pump | `pump_pending` 合并投递，SDK work queue 非阻塞；失败不另建队列。 |
| SPI device | 595/W5500 各 queue_size=1，单传输≤16384B | 共享有限入口锁，同步事务，无应用异步事务链。 |
| 扫描缓存 | 适配器及配网各最多 64 项，每页 8 项 | 固定数组，截断记录，SDK 扫描结果消费后清理。 |
| 扩展注册/应答 | 最多 32 handlers；每会话 2048B data，应答编码上限 2304B | 表满拒绝；固定编码数组不随请求数增长。 |
| 核心请求/响应 | 7 会话×8=56 条普通请求，每会话 16 个响应占位 | 数量或正文池耗尽拒绝；响应/TX 耗尽关闭来源，控制者同步停机。停止使用独立合并状态，不占普通请求队列。 |

队列 payload 表不含 RTOS 控制块和分配器开销。目标 ABI 的 `StaticQueue_t` 为 84B、`StaticTask_t` 为 96B；运行期有 17 个数据队列（包含 UART/RMT 与网络驱动事件队列）和 12 个信号量/互斥量。队列控制块合计约 2436B，仍不包含 SDK 自建队列、ring buffer 管理结构和分配器元数据。SDK/FreeRTOS 升级必须重算。

已固定的 SDK 网络配置包括：lwIP sockets=10、TCP send/window 各 5760B、TCP/UDP receive mailbox 各 6、默认事件队列 32、Wi-Fi static RX buffers=10、dynamic RX/TX buffers 各最多 32；HTTPD 客户端槽为 4、请求头≤1024B、URI≤512B、backlog=5。应用没有为超额连接或请求创建无界溢出队列。SDK 达到内存/连接限制仍可能拒绝分配，不能把“缓存有界”解释为“所有最大值可以同时成功分配”。

## 任务栈及堆余量

| 任务 | 分配栈 B | 优先级 |
| --- | ---: | ---: |
| gs_control | 10240 | 10 |
| gs_adc | 3072 | 9 |
| gs_uart_rx | 3072 | 8 |
| gs_eth | 4096 | 3 |
| gs_sta | 4096 | 3 |
| HTTPD | 4096，当前 SDK 默认值 | 3 |
| gs_store | 4096 | 2 |
| 合计 | 32768 | — |

这些是分配上限，不是实测栈消耗。还需计入 FreeRTOS/系统事件、TCPIP、Wi-Fi、timer、W5500 驱动等 SDK 任务和缓冲。

即使只计运行期应用已知 payload（包括 NVS 请求/结果）、上述任务栈及 RTOS 控制块，动态分配也超过 **71KiB**，尚未计入 SDK 网络/驱动、分配器开销和碎片。119980B 的名义空间扣除这些后余量有限，**未测的堆高水位与最大连续块是硬件验收开放项**。不能用静态预算、主机 sanitizer RSS 或模拟队列占用推算其通过。

## 服务预算与时间界限

控制入口按 UART service → 网络/WS service → dispatcher tick → UART service 执行：UART 每次最多 feed 256B、TX 128B，WS 每次轮转 feed 一包≤256B，dispatcher 优先处理停止、推进安全检查、再执行至多一条普通请求。HTTPD pump 每连接每轮最多一次非阻塞发送。控制任务计划周期为 20ms，采样 timer 为 5ms；迟到不补跑历史运动/序列。

由此只能得出每轮工作的数量边界。例如 4 个持续有输入的 WS 在无故障、控制轮次持续发生时，轮转至多 4 次 service 获得一包机会；这不是 80ms 的实测保证。WS 的 2s 发送/15s 传输超时、半行 2s 超时和应用看门狗都需控制/HTTPD 入口实际得到调度；上游同一流中的 S 也不能越过尚未接收的字节。

NVS 在全停状态下同步等待，SPI/ADC/网络 SDK 的真实执行与中断代价不由主机替身计时。板上测量方法与开放结果见 [故障回归报告](concurrency-fault-regression.md#板上仍需完成的记录)。
