# 定时序列状态机

实现位于 [`command_sequence.c`](../src/core/command_sequence.c)，由 `gs232b_control_tick` 驱动，与上传、会话、运动检查共用串行边界。序列状态只有控制核心一份；`gs232b_control_snapshot.sequence` 是 N 和状态查询使用的值快照。板级入口仍是构建基线，实际运动任务需接入同步执行端口并周期调用 tick。

| 状态 | 序号与动作 | T 行为 |
| --- | --- | --- |
| `EMPTY` | 当前/总数均为 0，无计时。 | 返回错误。 |
| `LOADED_WAIT_T` | 完整验证并成功下发首点后进入；当前序号为 1，不等待机械到位。 | 从实际执行接受时刻 t0 启动计时，不重新下发首点。 |
| `RUNNING` | 到达截止时刻后下发下一点，成功接纳才更新序号。 | 返回 CR，保留 t0、截止时间、序号和目标。 |
| `COMPLETED` | 最后一点已下发，停止步进；保留目标和数据，机械定位继续，N 保持总数/总数。 | 返回错误，重新加载后才能开始。 |

N 经现有响应编码器输出 `=nnnn=mmmm\r\n`；没有序列时输出 `=0000=0000\r\n`。序号表示已下发的点，不表示到位数。`next_deadline_us` 仅在 RUNNING 中非零；其余状态为 0。完成后的空闲或显式控制权释放保留末点序号和数据。

间隔 s 取 1～999 秒。首点在加载提交时下发，第 i 点（i≥2）的绝对截止时间为 `t0 + (i−1) × s`。下一截止时间始终从 t0 和点序号计算，不从本次实际执行时刻累加，不等待上一点到位。开始前检查全部截止时间是否可用 uint64 微秒表示；溢出时拒绝 T，保留等待状态和首点。

每个 tick 最多下发一个序列点。若当前时刻 d 尚未到下一截止时间 D，则等待；`D ≤ d < D+s` 时允许下发该点；`d ≥ D+s` 时锁定 `SEQUENCE_LATE / TIMEOUT` 并全停，禁止补发。末点也遵守这一迟到上限。运动推进前先检查一次，运动 tick 后、下发新点前再次读取时钟检查，避免执行端耗时跨过下一截止时间。运行中检测到时钟倒退也按序列故障处理。

独立停止槽先于上述检查执行。超期时不调用 `sequence_target`，清除序列、普通队列和输入预约，作废旧半行及 epoch，撤销所有权。后续点被执行端拒绝时锁定 `SEQUENCE_TARGET` 并清任务全停；若运动层已经记录输出或反馈故障，保留首次诊断。停机失败保留输出未知，后续 tick 不自动重试。显式清故障不恢复旧序列。

| 操作 | 序列及轴动作 |
| --- | --- |
| 任意长格式 M/W 成功 | 共用存储原子替换，取消旧计时，下发新首点，进入等待 T；N 变为 1/新总数。 |
| 任意单点 M/W 成功 | 清除旧序列、序号和计时，执行新定位。 |
| M/W 替换旧序列 | 新命令未涉及、但旧序列拥有的轴先停止；W→M 停 EL。与旧序列无关的另一轴手动动作保留。 |
| 参数、权限、输入或普通执行拒绝 | 保留旧序列、目标和计时，释放本次输入预约。 |
| 裸 M/W | 先检查权限，再清序列、全停并返回错误。 |
| R/L/U/D | 成功执行后清序列和计时；只替换指定轴动作，另一轴已下发的动作继续。 |
| A/E | 清序列，作废旧输入并停止指定轴，另一轴动作继续，保留控制权。 |
| S、控制者关闭、运动或通信丢字节故障 | 清序列、全停、作废旧输入并撤权。 |
| 查询、帮助、空行、X1～X4 | 保留序列及计时；交互中的 N/空行继续遵循交互权限规则。 |
| P36/P45 或 P36 下 Z 实际变更 | 两轴已知停止、计时未运行且无交互时才允许；成功提交设置后清序列。重复模式和 P45 下 Z 保留序列。 |

执行端接入 `sequence_target(ctx, plan)` 时只原子接纳计划内的机械角目标，不能再次换算显示坐标，也不能维护另一份计时器。可直接调用 `gs232b_motion_goto`；`fault(ctx, code, error)` 可调用 `gs232b_motion_abort`。T 由核心处理；N 完成回调读取控制快照并使用 `GS232B_RESPONSE_SEQUENCE` 编码。所有回调有界、非阻塞，不得重入修改控制器。

运行 `python3 scripts/test.py --host-only`。定时、生命周期和故障三个测试文件使用虚拟微秒时钟，不依赖睡眠或实际电机；1～999 秒全部遍历，最大 M/W 序列分别完整执行 3800 点/1900 对，并验证逐字节上传和查询期间仍能按时步进。
